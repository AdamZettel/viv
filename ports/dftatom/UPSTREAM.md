## What was ported

| Viv file | Upstream file | What |
|---|---|---|
| `dftatom.viv` | `src/mesh.f90` | the exponential mesh and its derivative |
| | `src/ode1d.f90` | `integrate` (seventh-order end-corrected trapezoid rule), node counting, `get_min_idx`, the Adams formulas, the four-point midpoint interpolation |
| | `src/rschroed.f90` | the Schrödinger pair: Runge-Kutta start, outward and inward implicit Adams-Moulton |
| | `src/rdirac.f90` | the Dirac pair, the same way, with the point-nucleus start |
| | `src/reigen.f90` | `solve_radial_eigenproblem`: bisection on the node count, the perturbative correction at the turning point, upstream's failure codes |
| | `src/rpoisson.f90` | the outward predictor-corrector Poisson solver |
| | `src/energies.f90` | hydrogen-like energies (Schrödinger and Dirac), the Thomas-Fermi starting potential |
| | `src/dft.f90` | VWN correlation, Slater exchange, the relativistic exchange correction, `rho2V`, `V2rho`, `KS_step`, the variational total energy |
| | `src/mixings.f90` | `mixing_anderson` with its energy criterion |
| | `src/drivers.f90` | `atom_lda` and `atom_rlda`, as one `atom_scf` |
| `states.viv` | `src/states.f90` | NIST's ground configurations for Z = 1 to 92, generated by `tools/gen_states.py` |
| `atom.viv` | `src/drivers.f90`, `tests/lda/conv_lda.f90`, `tests/rlda/conv_rlda.f90` | the exported program: settings, one SCF run, its results |
| `tests.viv` | `tests/Z92n7all/Z92_nonrel.f90`, `Z92_rel.f90` | upstream's hydrogen-like uranium tests |

The algorithms, their order of operations and their constants are upstream's. With the same `exp`,
`log`, `pow` and `atan` the port returns the same doubles as upstream's Fortran on every case in
`COMPARISON.md`.

## What was not ported

- The alternative integrators upstream keeps beside the ones it uses: `rschroed_other.f90`,
  `rdirac_other.f90`, `rpoisson_other.f90`, `ode1d_other.f90`, and the other integration rules
  of `ode1d.f90` (trapezoid of orders 1, 3 and 5, Simpson, Adams). `integrate` is upstream's
  default, `integrate_trapz_7`.
- `mixing_linear` and `mixing_linear_adapt`; the drivers use `mixing_anderson` only.
- `interpolation.f90`, `lapack.f90`, `utils.f90` (string and file helpers), `c_dftatom.f90`
  and the Cython wrapper.
- The tests that use the parts above or a potential of their own: `oscillator`, `well`,
  `pseudopotential`, `mixings`, `double_min`, `boron`, `atom_U`, `uranium`.
- The scalar-relativistic equation, which upstream does not implement either.
- The Dirac start for `Z = 0` (a potential with no nucleus, which upstream's pseudopotential tests
  use). The port stops with a message.

## Differences in behavior

1. **SCF that does not converge.** Upstream's `mixing_anderson` calls `stop_error`. The port
   returns the last iterate with `scf_converged = false`, and the program's test "the SCF loop
   converged" fails.
2. **A radial solve that fails** stops the run in both, with upstream's `converged` code in the
   message.
3. **The math library.** Viv computes `exp` correctly rounded and `log`, `pow` and `atan` with
   musl's fdlibm, in every engine. The platform `exp` that gfortran calls on macOS is off by one
   ulp on some arguments, so with the platform's libm the Fortran and the port differ: at most
   1.9e-9 Hartree in E_tot and 6.7e-10 in an eigenvalue (uranium, LDA), below the SCF tolerance
   of 5e-9. Linked with Viv's libm (`oracle/vmath_shim.c`) the Fortran returns the port's
   doubles. See `COMPARISON.md`.
4. **Fortran's `sign(1, -0.0)`** is -1; the port's node counter treats -0.0 as positive. No case
   in `COMPARISON.md` produces a negative zero (they all match upstream bit for bit).
5. **Names.** The exported program spells the atomic number `z` and the number of mesh intervals
   `n` (the export lowers parameter names; the Python wrapper accepts `Z=` and `N=`), and calls
   the mesh `mesh` (a result named `r` collides with a name in the generated C). The orbital
   labels `orbital_n`, `orbital_l` and `orbital_kappa` are arrays of doubles holding integers, because
   `tools/export/check.py` cannot yet print an `[Int]` result. `orbital_kappa` is 0 in a
   nonrelativistic run.
6. **Relativistic orbital order** is upstream's: for each `l > 0` level, `j = l - 1/2`
   (`kappa = l`) first, then `j = l + 1/2` (`kappa = -l - 1`), with the electrons shared
   `2l : 2l + 2`.
7. **The radial functions** of each orbital are kept in the SCF state (`AtomState.orbitals`) but
   not returned by the exported program; the density and the potential are.
