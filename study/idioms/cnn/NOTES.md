# A CNN on the 8x8 digits, in Viv

Source: https://github.com/pytorch/examples @ `acc295dc7b90714f1bf47f06004fc19a7fe235c4`
(shallow clone at `viv-wt/src/cnn`). The ported part is `mnist/main.py`: `Net` (lines 10-34),
`train` and `test` (lines 36-70). The network is the same layer for layer: conv 3x3, ReLU,
conv 3x3, ReLU, 2x2 max pool, dropout(0.25), flatten, linear, ReLU, dropout(0.5), linear,
log-softmax + NLL loss, and `StepLR(step_size=1, gamma=0.7)`. The input is sklearn's
`load_digits` (8x8, pixels / 16) instead of MNIST, the channel counts are smaller, and the
optimizer is Adam instead of Adadelta (the task allows SGD or Adam; Viv's `lib/optim` has Adam).

## Files

Run from the worktree root: `python3 study/idioms/cnn/ref.py` (run inside `study/idioms/cnn`),
then `viv run study/idioms/cnn/cnn.viv` (see F16 for why the directory matters).

## What convolution, reshapes, batching and indexing cost

- **Convolution.** torch: `nn.Conv2d(1, C1, 3, 1)` and `self.conv1(x)`; backward is free.
  Viv: `im2col` (24 lines), `col2im` (24), forward (18), backward (24). The work happens in
  one `@` each way; the rest is moving between the `(B, O, Ho, Wo)` layout and the
  `(B*Ho*Wo, O)` matrix, which in numpy is `Z.reshape(B, Ho, Wo, O).transpose(0, 3, 1, 2)`
  and in Viv is a 4-deep loop in each direction (F2, F4).
- **Reshapes.** `torch.flatten(x, 1)` becomes `take(P, flat_index2(n, FLAT))` plus a
  10-line helper that builds the index array, and its adjoint `take(dD1 * M1, flat_index4(...))`
  plus a 13-line helper (F2). Weights of rank 4 had to be stored as `(O, C*9)` matrices (F10).
- **Batching.** torch: `Xtr[idx]`. Viv: a function `images()` with a 3-deep loop and a
  `round()` on every float index (F14). The batch size travels as an extra argument next to
  the arrays (F18).
- **Indexing.** Rank-4 element indexing `X[b, c, i + u, j + v]` is direct and reads as the
  math (W1). What is missing is anything above an element: slices (`M[:, j]`, `A[:] = B`),
  boolean masks (`Y > 0`), axis reductions (`sum(A, 0)`), row broadcasting (`M + b`).

## Friction ledger

Each entry: what I wrote, what I wanted, the Python/Julia equivalent, category, severity
(1 cosmetic, 2 costs lines, 3 blocks or distorts the algorithm), and how often.

### F1. No automatic differentiation over arrays (severity 3, 7 layers)

Every layer's adjoint is written by hand: `conv2d_bwd`, `col2im`, `relu4_bwd`, `relu2d_bwd`,
max-pool scatter, `dense_bwd`, dropout (`dD2 * M2`), and the flatten adjoint; then the step
function runs them in reverse order (lines 339-356). Changing the architecture (adding a
layer, padding, stride 2) means deriving and writing a new backward and a new gradient check.

Had to write:
```
dD2 = dense_bwd(D2, W2, dL, dW2, dc2)
dH = relu2d_bwd(H, dD2 * M2)
dD1 = dense_bwd(D1, W1, dH, dW1, dc1)
dP = take(dD1 * M1, flat_index4(n, C2, 2, 2))
dA2 = zeros(n, C2, 4, 4)
put(dA2, arg, dP)
dA1 = conv2d_bwd(A1, K2, relu4_bwd(A2, dA2), dK2, db2)
conv2d_bwd(X, K1, relu4_bwd(A1, dA1), dK1, db1)
```
Wanted: `grad = gradient(loss_of, theta)` over the forward function.
Python: `loss.backward()`. Category: missing builtin. Differentiable
arrays were v5 (not built then); the scalar tape (v2) does not cover arrays.

### F2. No `reshape` / `flatten` (severity 2, 3 places)

Had to write a helper that builds an index array, then gather:
```
def flat_index4(d1, d2, d3, d4) {
    idx = zeros(d1, d2, d3, d4)
    for a to d1 { for b to d2 { for c to d3 { for d to d4 {
        idx[a, b, c, d] = ((a * d2 + b) * d3 + c) * d4 + d
    ...
F = take(P, flat_index2(n, FLAT))
dP = take(dD1 * M1, flat_index4(n, C2, 2, 2))
```
Wanted: `F = reshape(P, n, FLAT)` and `dP = reshape(dD1 * M1, shape(P))`.
Python: `torch.flatten(x, 1)`, `x.view(n, -1)`. Category: missing builtin. `probe/reshape.viv`:
`unknown function 'reshape'`. The same gap forces the loops that move the conv product
between `(B*Ho*Wo, O)` and `(B, O, Ho, Wo)` in `conv2d_fwd` and `conv2d_bwd` (numpy:
`Z.reshape(B, Ho, Wo, O).transpose(0, 3, 1, 2)`; wanted a `permute`).

### F3. No elementwise comparison or `where` (severity 2, 2 functions)

`probe/r4.viv`, `probe/where.viv`: `A > 0.0` on an array stops with
"only + - * / are supported elementwise on arrays". ReLU backward is therefore a nested loop,
written twice because a function cannot be rank-generic (F4):
```
def relu4_bwd(Y: Arr, dY: Arr) {      # 15 lines, 4 nested loops
    ...
                    if Y[b, c, i, j] > 0.0 {
                        dX[b, c, i, j] = dY[b, c, i, j]
```
Wanted: `dX = where(Y > 0.0, dY, 0.0)` or `dY * (Y > 0.0)`.
Python: `dY * (Y > 0)`. Julia: `dY .* (Y .> 0)`. Category: missing builtin.

### F4. No rank-generic code (severity 2, 7 functions)

`shape(X)` returns an array; there is no unpacking, no `zeros(shape(X))`, no `zeros_like`, no
splat. Every rank-4 function begins with the same five lines, and each allocation spells all
four dimensions:
```
s = shape(X)
B = s[0]
C = s[1]
H = s[2]
W = s[3]
dX = zeros(s[0], s[1], s[2], s[3])
```
Wanted: `B, C, H, W = shape(X)` and `dX = zeros_like(X)`.
Python: `B, C, H, W = X.shape`; `torch.zeros_like(X)`. Julia: `B, C, H, W = size(X)`;
`zero(X)`. Category: syntax / missing builtin.

### F5. No slices; assigning to an array parameter silently rebinds (severity 2, 3 places)

To return a gradient through an out-parameter, the result is copied element by element:
```
G = transpose(dZ) @ im2col(X)
for o to O {
    for k to shape(K)[1] {
        dK[o, k] = G[o, k]
    }
}
```
Wanted: `dK[:] = transpose(dZ) @ im2col(X)`, or (better, F6) return it.
Python: `dK[...] = dZ.T @ cols`. Category: syntax. `probe/slice.viv`, `probe/copyout.viv`:
`M[:, 1]` and `dK[:] = ...` are parse errors.
The trap: `dK = G` inside the function compiles, runs, and leaves the caller's `dK` all zeros
(`probe/outparam.viv` prints 0). No warning in either engine. Category also:
tooling/error message. `put(dK, flat_index2(...), G)` works but needs the F2 helper.

### F6. No multiple return values (severity 2, 4 functions)

`probe/tuple.viv`: `return x, 2.0 * x` is a parse error. So `conv2d_bwd` returns `dX` and
fills `dK`, `dbias` passed in; `dense_bwd` the same; `maxpool_fwd` returns `Y` and fills `arg`;
`step` returns the loss and fills `grad` and `logits`. Each caller pre-allocates with the right
shape:
```
dK2 = zeros(C2, C1 * 9)
db2 = zeros(1, C2)
dA1 = conv2d_bwd(A1, K2, relu4_bwd(A2, dA2), dK2, db2)
```
Wanted: `dA1, dK2, db2 = conv2d_bwd(A1, K2, dA2r)`.
Python: `return dX, dK, db`. Category: control flow / syntax.

### F7. No axis reductions (severity 2, 2 places)

Bias gradients are column sums, done in the loops of `conv2d_bwd` and `dense_bwd`:
```
for r to len(dY) {
    dbias[0, o] = dbias[0, o] + dY[r, o]
}
```
Wanted: `dbias = sum(dY, 0)`. Python: `dY.sum(0)`; `dY.sum((0, 2, 3))` for the conv.
Category: missing builtin (`probe/sumaxis.viv`: `sum` takes one argument).

### F8. No row broadcasting (severity 2, 2 places)

`probe/bcast.viv`: `M + b` with `M` 3x2 and `b` length 2 is "array shape mismatch". Adding the
bias is a loop in `dense_fwd` and folded into the layout loop of `conv2d_fwd`:
```
Y = X @ transpose(W)
for r to len(Y) {
    for o to len(W) {
        Y[r, o] = Y[r, o] + bias[0, o]
```
Wanted: `Y = X @ transpose(W) + bias`. Python: `x @ W.T + b`. Julia: `X * W' .+ b'`.
Category: missing builtin.

### F9. No `+=` into an element (severity 1, 6 places)

`probe/compound.viv`: "compound assignment into an array element is not supported". The
error message gives the rewrite, which helps, but the rewrite repeats a four-index expression:
```
dX[b, c, i + u, j + v] = dX[b, c, i + u, j + v] + dcols[r, c * 9 + u * 3 + v]
```
Wanted: `dX[b, c, i + u, j + v] += dcols[r, c * 9 + u * 3 + v]`. Python: the same `+=`.
Category: syntax. Occurs in `col2im`, both bias sums, the accuracy count.

### F10. Parameters and literals are at most rank 2 (severity 1, 2 places)

`lib/params` declares tensors as `rows x cols`, and array literals of rank 3 or more are refused
(`probe/lit.viv`: "matrix rows must be 1-D arrays"). A conv kernel `(O, C, 3, 3)` is stored as
`(O, C*9)` and the ordering `c * 9 + u * 3 + v` is written out by hand in `im2col`/`col2im`.
This happens to be the layout im2col wants, so it cost little here, but a kernel cannot be read as
`K[o, c, u, v]`. Wanted: `param_declare(model, C2, C1, 3, 3)`. Python: `nn.Conv2d` owns a
rank-4 weight. Category: missing data structure.

### F11. Parameters are a flat vector plus integer handles (severity 2, 3 blocks of 8 lines)

No records in the interpreter (records are C-backend only, reference.astro line 106), so there
is no `Conv2d` or `Net` value. Every tensor is declared, initialized, read, and gradient-added
through its handle, eight times each:
```
CONV1 = param_declare(model, C1, 9)
...
param_set(theta, model, CONV1, INIT_CONV1)
...
K1 = param_get(theta, model, CONV1)
...
param_add(grad, model, CONV1, dK1)
```
Wanted: `net.conv1.weight` as a field, and one call that walks all parameters.
Python: `model.parameters()`, `model.load_state_dict(init)`. Category: missing data structure.
The upside is that the optimizer sees one flat `theta` and needs no knowledge of the model (W4).

### F12. Output: 6 significant digits, no format strings (severity 2, every printed number)

`print(x)` and `show x` print `%g` (`probe/fmt.viv`: `0.333333`), and strings exist only in
docstrings, test names and `narrate`, so a line such as
`epoch 0 step 3 loss 2.316130...e+00` cannot be produced (`probe/precision.viv`). The port
prints bare losses and compares against torch inside the program instead of by `diff`.
Wanted: `print("epoch {epoch} step {s} loss {loss:.15e}")`. Python: an f-string.
Category: strings/IO.

### F13. `for` has no start or step (severity 1, 1 place)

`probe/range_step.viv`. The batch loop is `for s to steps` with `s * BATCH + k`.
Wanted: `for start in 0 to N_TRAIN by BATCH`. Python: `range(0, N, BATCH)`. Category: syntax.

### F14. Labels and indices are floats (severity 1, 3 places)

Class labels and row numbers are `Num`, so gathering a batch reads
`data[round(rows[k]), i * 8 + j]` and `Y_TRAIN[round(rows[k])]`. It works (indexing with an
integral float is allowed), but `round` is noise. Python: `torch.long` labels,
`Xtr[idx]`. Category: type system.

### F15. Optimizer settings are array slots (severity 1, 1 place)

StepLR is `opt[OPT_LR] = opt[OPT_LR] * GAMMA`: the optimizer is an array indexed by named
constants. Wanted: `opt.lr = opt.lr * GAMMA`. Python: `StepLR(opt, 1, gamma)`, or
`g["lr"] *= gamma`. Category: missing data structure (same cause as F11).

### F16. `#! use lib/...` depends on the current directory (severity 2, 1 place)

`cd study/idioms/cnn && viv run cnn.viv` fails with
"`#! use lib/nn`: no module by that name (looked for lib/nn.viv beside the program and under )"
(the search root is empty). Running from the worktree root as
`viv run study/idioms/cnn/cnn.viv` works. The DDPM study found the same thing (its F13).
Category: tooling/error message.

### F17. No shuffle / `randperm` (severity 1, 1 place)

There is `sort` and `rand` but no permutation builtin, so a Viv-only version would write
Fisher-Yates by hand. Here the order came from torch to match it exactly, so this cost nothing.
Python: `torch.randperm(n)`. Category: missing builtin.

### F18. Sizes travel next to arrays (severity 1, ~6 call sites)

`lib/nn` functions take the dimensions explicitly: `cross_entropy_fwd(L, y, n, CLASSES)`,
`argmax_rows(test_logits, N_TEST, CLASSES)`, and `step` takes `n`. `len(A)` and `shape(A)`
exist, so the library could read them. Python: `F.nll_loss(out, y)`. Category: type system
(library convention).

### F19. `cc` warning from the C backend (severity 1, 1 place)

`optim_step` compiles to a `viv_apply(...).num;` statement whose value is unused, and
`cc -O2` prints `-Wunused-value`. Output is unaffected. Category: engine gap (cosmetic).

### F20. Interpreter speed (severity 1)

29.8 s CPU in the interpreter vs 0.25 s native (about 120x). It fits the budget at this size,
but a 28x28 MNIST batch would not. The time is in the scalar loops of `im2col`, `col2im`, the
layout moves and the ReLU backward, which F2, F3 and F8 would turn into builtins. Category:
performance.

## Wins

- **W1. The convolution reads as the math.** `im2col` is a direct six-loop statement of
  "every window becomes a row", `cols[r, c * 9 + u * 3 + v] = X[b, c, i + u, j + v]`, and the
  convolution is `im2col(X) @ transpose(K)`. The backward is `transpose(dZ) @ im2col(X)` and
  `col2im(dZ @ K, shape(X))`. This is shorter than a numpy `as_strided` im2col and has no
  stride arithmetic to get wrong.
- **W2. Gather/scatter.** `take`/`put` make max-pool backward one line: `put(dA2, arg, dP)`
  scatters through the saved argmax indices, which is what torch does inside `max_pool2d`.
- **W3. ReLU forward on any rank:** `max(conv2d_fwd(X, K1, b1), 0.0)`, same as `F.relu`.
- **W4. The library did the optimizer and the loss.** `#! use lib/optim` gives
  `adam(LR, 0.9, 0.999)`, `optim_state(model)`, `optim_step(...)`: three lines, and it matches
  `torch.optim.Adam` to 1e-15 over 192 steps. `lib/nn` gives `cross_entropy_fwd/bwd` and
  `argmax_rows`; `lib/params` the flat parameter vector.
- **W5. The gradient check sits next to the code.** A `test` block with `assert_lt` runs the
  central-difference check of `conv2d_bwd` on every run, in both engines.
- **W6. Whole-array expressions where they exist:** `worst_theta = max(abs(theta - REF_FINAL))`,
  `D1 = F * M1`, `dD2 * M2`.
- **W7. Reproducible randomness.** `rand()` is MINSTD with a documented seeding rule, so
  `ref.py` replays the dropout masks exactly; with torch's own dropout that is not possible.
- **W8. Both engines agree to the byte, and the native build runs in 0.25 s**, faster than the
  torch reference on this size.
- **W9. Error messages that give the rewrite.** The `+=` error says
  "write `a[i] = a[i] + ...` instead"; the `for ... in` error explains `for i to n`.
